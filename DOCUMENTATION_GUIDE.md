# Documentation Guide

Keep these Markdown files in the repository root so the project plan and rules are visible to anyone opening the repository.

```text
rabin-portfolio/
├── README.md
├── PROJECT_PLAN.md
├── RESTRICTIONS_AND_RULES.md
├── WORK_LOG.md
├── CHANGELOG.md
└── docs/
    ├── PROJECT_OVERVIEW.md
    ├── ARCHITECTURE.md
    ├── DIRECTORY_GUIDE.md
    ├── API_REFERENCE.md
    ├── DATABASE.md
    ├── ENVIRONMENT.md
    ├── SECURITY.md
    ├── ROADMAP.md
    ├── DEVELOPMENT_WORKFLOW.md
    └── CONTRIBUTING.md
```

## How to use the documents

- `PROJECT_PLAN.md` — master plan, phases and definition of done.
- `RESTRICTIONS_AND_RULES.md` — rules that must be followed during development.
- `WORK_LOG.md` — dated record of what has actually been completed and what remains.
- `docs/DIRECTORY_GUIDE.md` — explains what the folders/files in the repository do.
- `docs/DEVELOPMENT_WORKFLOW.md` — commands and safe workflow for baseline checks and future changes.
- Other `docs/` files — detailed project, architecture, API, database, environment and security references.

When a decision changes, update the relevant document and add an entry to `WORK_LOG.md`. Keep status labels honest: planned, in progress, verified complete, blocked or deferred.
